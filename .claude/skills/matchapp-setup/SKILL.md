# セットアップ（会話で設定を作る）

ユーザーと話しながら `config/` の4ファイル（`profile.md` `me.md` `style.md` `settings.json`）を埋める。
フォームのように一気に質問を並べない。**1回に聞くのは1〜2個まで**、選択肢と例を添えて答えやすくする。答えにくそうなら「とりあえずおすすめでいい？」と既定値を提案して進める。

## 進め方の原則

- 最初に「全部で5ステップ、10分くらい。あとからいつでも変えられる」と伝える
- 各ステップの終わりに、書く内容を短く見せて「これでいい？」と確認してからファイルに書く
- ユーザーが言っていないことを勝手に盛らない。空欄は `TODO` のまま残してよい（あとで埋められる）
- スクショ（自分のプロフ、うまくいったトーク）をもらったら、読んでテキストだけ書き、画像は保存しない
- 本名・勤務先・住所・アプリのIDなど、特定につながる情報は書かない。もし言われても「ここには書かんとくね」と断ってから省く

## ステップ0：準備

1. `config/` が無ければ `config.example/` を丸ごと `config/` にコピーする（`cp -r config.example config`）
2. 絶対ルールを3行で伝えて、了解をもらう
   - 送信は自分の手で（Claudeは案を出すだけ。自動操作はアカウント停止）
   - 写真は保存しない
   - このリポは必ず非公開（Private）で使う
3. `git remote -v` などでリポが公開になっていないか気になるときは、ユーザーにGitHubの設定でPrivateか確認してもらう

## ステップ1：あなたについて → `config/profile.md`

聞くこと（2つずつ）：
1. 「なんて呼べばいい？」「説明はどんな話し方がいい？（例：関西弁タメ口で短く／標準語タメ口／丁寧語）」
   → 聞いた直後から、その話し方に切り替える
2. 「使ってるアプリは？」「自分はどんな人で、どんな相手と出会いたい？（性別・年代など、言える範囲で）」
3. 「メッセージでどこまで持っていきたい？（例：インスタ交換→電話→デート／LINE→デート）」「真剣寄り？気軽寄り？」
4. 「相手のプロフにあったら拾いたい話題は？」「避けたい話題は？」

## ステップ2：自分のプロフ → `config/me.md`

- 「アプリの自分のプロフ、スクショで送ってもらうのが早い。テキストで貼ってもOK」と頼む
- 基本情報／自己紹介文の要点／趣味・タグに分けて書く
- 載せていないことは書かない（共通点の捏造を防ぐため）

## ステップ3：返信スタイル → `config/style.md`

ここが一番大事。次の順で聞く。

1. **キャラ**：「どんな感じで見られたい？」と聞き、選択肢を出す
   - 余裕系（焦らない、褒め＋軽い決めつけ、要所で一歩踏み込む）
   - 誠実系（丁寧、共感と質問多め、押さない）
   - おもしろ系（ノリ、いじり多め、テンポ重視）
   - 聞き上手系（相手に話させる、リアクション重視）
   - 混ぜてもOK
2. **口調**：「返信の言葉づかいは？（標準語／方言どのくらい）」「敬語はいつ外す？」「絵文字は使う？」「長さは？」
3. **うまくいった実例**：「前にうまくいったトーク、あったらスクショか文字で見せて」
   - もらえたら、そこから型を読み取って「お手本」に載せ、序盤の流れ・口調にも反映する。読み取った型を「こういうのが効いてそう」と説明して確認する
   - 無ければ、選んだキャラで短いお手本を1本作って見せ、直してもらう
4. **序盤の流れ**：「1通目〜3通目くらいで決まった型ある？」無ければキャラに合う型を2案出して選んでもらう
5. **NG**：「言いたくない・使いたくない言い回しは？」「前にスベったやつは？」

デフォルトで入れておく共通ルール（`matchapp-reply` に書いてあるので style.md に重複して書かなくてよい）は、ここで一言だけ紹介する：
根拠は相手の発言だけ／短く・相手の分量に合わせる／最後は返しやすいフック／質問は1通に1つ。
ユーザーが「それは違う」と言ったら、style.md に「上書き」として書く。

## ステップ4：段階と型 → `config/settings.json`

- `stages` と `tactics` の既定を、日本語ラベルで一覧にして見せる
- ゴール（ステップ1）に合わせて調整する。例：電話をしないなら `call` を消す、LINE派なら `contact` のラベルを「LINE交換」にする
- 序盤の型を作ったら、それ用の tactic を足す（例：`opener_torareru`: 「他の人に取られる前に」系）
- 変更が無ければそのままでよい

## ステップ5：仕上げ

1. `config/profile.md` の `setup_done` を `true` にする
2. `python3 scripts/check_setup.py` を実行し、残っている `TODO` を見せる（残っていても動く。あとで埋められると伝える）
3. 「一回ロープレして試す？」と聞く。やるならClaudeがユーザー役、ユーザーが相手役で数往復し、ダメ出しを style.md に反映する
4. ユーザーに確認してから `config/` をコミットする（初回は `main` に直接でよい）
5. 使い方を3行で伝える：スクショを送る→案が出る→送ったら「これ送った」。ときどき「分析して」

## 部分更新（「設定変えたい」と言われたとき）

- どのファイルのどこかを聞き、該当部分だけ見せて直す
- `profile.md` `me.md` `settings.json` はその場で直してコミットしてよい（ユーザーに確認して）
- `style.md` の変更は、ユーザー本人が言った変更ならその場で直してよい。Claudeがデータから提案する変更はブランチ＋プルリク
